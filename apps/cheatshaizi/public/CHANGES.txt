0. LICENSING - CHECK THIS FIRST
-------------------------------

A Mini Game is treated as a game, not a tool. Before building anything,
check the current Mini Game publishing rules (小游戏运营规范 / 游戏类目
资质要求) in the 微信公众平台 admin console:

    - 软著 (software copyright registration): expect to need it. The
      company can apply itself. Takes weeks to a few months.
    - 版号 (game publishing license): required for games with in-app
      purchases, and WeChat's requirements for free games have been
      tightening. A 版号 is applied for through a licensed publisher,
      not by the company directly, and takes months. Check whether a
      free game with no ads / no purchases currently needs one.
    - Category: avoid 棋牌 (board / card / dice gambling-style) categories,
      which are the strictest. Look for a 休闲 / 益智 / party-game style
      category, and check which 资质 each one requires.
    - If the company is registered outside mainland China, use the 海外主体
      path and check which game categories it allows.

If a 版号 turns out to be required, the Mini Program build is the fallback
(tool category, no 版号). Everything in sections 1-3 applies to both.

    Home scene  --PLAY-->  Cup scene, in the last mode played
    Home scene  --切换模式-->  Modes scene  (to change mode)
    Home scene  --玩法说明-->  Help scene
    Cup scene   --⚙-->  Home scene

Scenes are switched with app.go(name, arg) in js/main.js.
Add a 'modes' and a 'help' scene next to home and cup:

1.3 Controlled mode explanation overlay (new, drawn in js/cup.js)

    - Draws the 3x2 grid over the screen in the same positions as the

          first tap  = quantity  (1 2 / 3 4 / 5 0)
          second tap = face      (1 2 / 3 4 / 5 6)
    - Explains, in short lines:
          长按「摇」开启自定义
          第一次点击：选择数量
          第二次点击：选择点数
          1 是万能（飞），数量包含 1
          设置一次后自动关闭，再次设置需重新长按
          开盅后也可以设置
    - Explains the 🍶 toggle (kept, bottom-left in Controlled mode instead of
      mute):
          🍶 亮：设定的数量里会混入 1（飞）
          🍶 暗：只出现你选的点数，不混入 1
    - 不再显示 checkbox + 确定 button. On 确定 the overlay disappears and
      the cup scene works exactly as the current override mode:
          long-press 摇 -> double vibration -> invisible 3x2 grid ->

    - Unchanged gameplay for all four modes: tap 摇 to roll, swipe up to
      open, swipe down to close, shake animation, sound + mute.
    - ⚙ -> app.go('home'). The mode list is not shown on the way out.
    - Entering the cup scene stores the mode as the last mode played.

1.5 Keeping the mode screen out of the way (not hidden)
    The mode screen only appears when the player chooses to change mode.
    It stays one visible, labelled tap away, so nothing is hidden:
    - PLAY remembers the last mode played (local storage key 'lastMode',
      js/storage.js) and goes straight into it.
    - ⚙ on the cup scene returns to the launch screen, not the mode screen.
    - 切换模式 on the launch screen always opens the mode screen.
    - The help scene says so: "PLAY 会直接进入上次使用的模式。首页点
      「切换模式」可以更换。"
    - The review notes must say the same, so the reviewer knows where the
      four modes are.
    Do not go further than this: no unlabelled or disguised way to reach
    the mode screen. That is the hidden-feature problem again.

      launch or splash screen, so check the current requirement before
      submitting, and move it back there if review asks for it.

      require (usually the splash / home screen).
    - Age rating (适龄提示) if the category requires it. Given the drinking
      context, expect 18+ or at least 16+.

      games, but check whether the chosen category requires anything
      from the game itself.
