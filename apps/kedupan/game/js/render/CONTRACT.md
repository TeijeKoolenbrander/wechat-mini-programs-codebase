# Render contract (frontend-ui <-> minigame-dev), v1

Spec: `docs/kedupan/spec.md` §6 (screens), §8.5 (open data domain), §10 (view models), §7 (share cards), §9 (ads), §6.11 (display modes). Same shape as 点将台's contract (`apps/dianjiangtai/game/js/render/CONTRACT.md`).

**Owners.** *Render* = frontend-ui: everything under `js/render/*` and `opendata/draw.js`, `opendata/index.js` (drawing only). *Logic* = minigame-dev: `core/*`, `js/vm.js`, `js/controller.js`, `js/store.js`, `js/api.js`, `js/mock-server.js`, `opendata/match.js` + `opendata/peer.js` (the data model of the open data domain, already written and tested), `js/share.js`, `js/ads.js`, ... Neither side restyles or re-formats the other's output: logic supplies every dynamic string pre-formatted, render owns fixed chrome and layout.

Every screen module `js/render/<screen>.js` exports `draw(ctx, vm, layout) -> hitAreas`.

- `vm` is the spec §10 view model plus the **extras** listed per screen. A missing extra falls back to the stated default. Strings marked *(logic)* arrive finished (`core/present.js` builds them); renderers never compute a number, a label or a sentence from data.
- `layout = makeLayout({windowWidth, windowHeight, pixelRatio, statusBarHeight, safeArea, menuRect})` (`layout.js`, copied from 点将台). `menuRect` is `wx.getMenuButtonBoundingClientRect()`; rebuild on resize and `onShow`. `layout.u(n)` scales points; all sizes below are points before `u()`.
- `hitAreas = [{id, x, y, w, h}]` in canvas px. **Later areas win** (`hitTest(hitAreas, x, y)`): concatenate `screen.draw(...)` then `overlay.draw(...)`. Ids ending `:block`, `sheet:body`, `sheet:scrim`, `coach:block` only swallow taps. `hitAreas.scrollMax = {<scrollId>: maxOffsetPx}` for scrollable regions; logic owns the offset (passes it back as `scrollY` / `sheetScroll`) and clamps to `scrollMax`. Keep `scrollMax` when concatenating overlay hits. Scroll ids drawn (all settled): `home:scroll`, `result:scroll`, `round:scroll`, `review:scroll` (also the archive set-end view), `sheet:list`, `board:list`, plus `card:scroll` (card reveal text; large text on short screens), `create:scroll` (pickClue on short screens) and `board:scroll` (the group / friend page scrolls as a whole with the open data list inside it). Every scroll region draws only when the content overflows. At scroll 0 the viewport is cut at a block boundary (QA-5, AC 70): no line or button is ever half visible, so the viewport can be shorter than the free area, and `scrollMax` is measured against that viewport (clamp to it as before). Home pins its two button rows when the page scrolls; the open data list (`opendata/draw.js`) is cut at the last whole row above the 最同频 footer (`drawView` also returns `viewportHeight`, `itemEnds`, `footerTop`).
- `hitAreas.ruler = {x0, x1, y, h}` is set by every screen that has a live ruler (see "Ruler input").
- Renderers are pure: no `wx`, no timers, no state. Animate from progress fields in the vm (`t` ms clock, `revealT` 0..1, `confetti.t`) and redraw each frame. Shipped render code requires only relative `.js` modules.
- Fonts: system only. Text never below 16 pt (20 pt in large text); prompt >= 28 pt (34 large); scores >= 40 pt (48 large). The renderer, not logic, keeps text inside its box (wrap prompt to 2 lines, shrink to fit, never clip).
- All content starts below `navBottom = capsule.bottom + (capsule.top - statusBarHeight)`; nothing drawn or tappable in the capsule's row on the right; in-game back is "‹ 返回" top-left. **The ruler and the primary button sit in the bottom 45%, above the bottom safe-area inset** (AC 69). Touch targets >= 48 x 48 pt. Design width 375; works 320-430 wide, 568-932 tall.
- Every network-backed screen draws its `loading` skeleton, `empty` and `error` states; errors show 重试 (logic routes it). Nothing traps the player: 返回 is always drawn and live.

## Display modes (all screens, spec §6.11)

Every vm carries `display: {largeText, highContrast, scale: 1|1.25, palette: 'standard'|'highContrast'}`; each `draw()` starts by applying it. Pass the same `display` in the overlay vm. Share cards always use the standard look.
- **Large text:** body >= 20 pt, prompt >= 34, scores >= 48, buttons >= 56 pt tall, ruler band >= 80 pt; result mini rulers become one per row with the prompt above; content scrolls (never clipped at 320 x 568).
- **High contrast:** white background, black ink, darker markers with 2 pt outlines, text >= 7:1, non-text >= 3:1 (default mode >= 4.5:1 body). Markers differ by **shape** in every mode (AC 71): you ▼, nation ◆, group ●, group member ○ (hollow), target ▮, late guess dashed ○.

## Shared widget: ruler  (`ruler.js`, used by card, create, round, result, archive)

`ruler.draw(ctx, L, spec)`, `spec = {x, y, w, h, left, right, needle: int|null, markers: Marker[], band: {from,to}|null, interactive: bool, revealT, t, hint: string|null, display}`.
- `left`/`right` are the end labels, drawn on sticky notes at the two ends (renderer-owned look). `needle` null draws **no** needle and, when `hint` is set, the hint text over the track (*logic*: '点一下或拖动，放上指针').
- `Marker = {pos: 0..100 (may be .5), kind: 'you'|'nation'|'group'|'member'|'target'|'late'}` (spec §10). Draw order: nation, group, member/late, target, then you on top. `band` is the host's tangerine target band (±2 around the hidden target; the number is never shown, AC 26). Tick marks every 10 steps, no numbers.
- `revealT` 0..1 slides ◆ ● ○ in from the ▼ position to their `pos`; 0 shows only ▼.
- Never shows a number, and never draws a needle the vm did not give (AC 14).

### Ruler input contract (the slider)

The renderer **never** turns touches into positions. It draws, reports geometry, and logic feeds raw touches to `core/ruler.js`:
1. Screens with a live ruler set `hitAreas.ruler = {x0, x1, y, h}` where `[x0, x1]` is the track span in canvas px (full width minus 16 pt margins: `core/ruler.makeTrack({x:0, width: layout.W})` gives the same numbers) and `y/h` the touch band (height >= 64 pt, >= 80 pt large text). The band hit area (`<screen>:ruler`) spans the **full width** so touches in the margins clamp to 0 / 100.
2. Logic: `touchstart` on `<screen>:ruler` -> `ruler.touchStart(id, x, track, now)`; `touchmove`/`touchend`/`touchcancel` for that finger are routed to the ruler **even outside the band** until it lifts; one finger at a time. The needle jumps to the finger; release keeps it. `<screen>:nudgeL` / `:nudgeR` -> `ruler.nudge(-1|+1)` (exactly one step, clamped; a no-op until the first touch, so draw the ‹ › buttons disabled while `needle === null`).
3. Logic passes `vm.needle = ruler.pos` (int or null) each frame. 就这儿 is drawn disabled while `canConfirm` is false (no needle, or submitting). While `phase === 'submitting'` the ruler is locked (logic) and the needle drawn in its locked look.
4. Sounds/vibration (tick every 5 steps, chime + `vibrateShort` + confetti on `reveal.bullseye`) are logic's. Render only draws confetti from `confetti = {t: 0..1, seed}`.

- GroupPage states (all must draw, none blocks 返回): `noGroup` ("在群聊里点开本游戏的卡片，就能看到本群的默契度" + optional 分享到群), `checkingGroup` (skeleton "正在确认群聊…"), `groupFailed` (same as noGroup), `loading` (skeleton rows), `notPlayed` (`countText` "已完成 N 人", rows hidden: "完成今日刻度后查看本群默契" + 去答题; trend + rounds list still drawn), `ready` (`mqText` is a plain number as a string, e.g. '81', or null; the renderer draws the label 本群今日默契度 next to it; `mqText` big, `countText`, `divisiveText`, the open data list from `sharedCanvas`, trend strip from `trend` ('—' where `value` null), rounds list, 分享到本群), `small` ("完成人数满 3 人后计算本群默契度"; list still drawn), `empty` ("本群今天还没有人完成" + 去答题), `serverError` ("本群数据暂时打不开" + 重试), `privacyDenied` ("查看群友昵称需要同意《用户隐私保护指引》" + 查看指引 + 同意并查看; the anonymous list and stat lines still draw), `unauthorized` (anonymous list + "开启「微信朋友关系」可显示群友昵称" + 去设置开启).
- FriendBoard states: `loading`, `ready`, `empty` ("还没有好友完成今日刻度"), `serverError`, `privacyDenied`, `unauthorized`; `mode 'selfOnly'` draws `selfText` and the note "好友自报" rows come from the open data canvas without rank numbers.
- Banner: `banner = {show, reservedHeight}`; only `ready`/`empty` honour it. Geometry helpers `boardRect(L, banner)` (open data canvas + `postMessage` width/height) and `bannerRect(L, banner)` (native banner, >= 24 pt above/below neighbours) are exported by `render/index.js`.
- Hit ids: `board:back`, `board:retry`, `board:goPlay`, `board:share`, `board:contract`, `board:agree`, `board:openSetting`, `board:list` (drag; forward `{type:'scroll', offset}`; clamp the offset to `[0, serverRows * rowH * layout.s]`, `rowH` 66, 100 in large text), `board:round:<roundId>` (a row of the rounds list; logic opens the round entry).

## archive  (`archive.js`: list, day review, set end)
- List vm: `{kind:'list', state: 'loading'|'ready'|'empty'|'error'|'offline', bestStreakText, hasMore, items:[{dateKey, issueNo, dateText, statusText}], banner, display}` + `scrollY`, `t`. `empty` "还没有往期，明天再来"; `offline`/`error` "往期需联网查看" + 重试 (a cached page may still draw, with an "离线" tag *(logic)* in `bestStreakText`'s line via `offlineTag: bool`). Hit ids: `archive:back`, `archive:retry`, `archive:item:<dateKey>`, `archive:more` (加载更多, only if `hasMore`), `archive:list` (drag).
- Review vm (day played as the daily, read-only): `{state, dateKey, issueNo, kind:'review', cards: CardText[5], finals: number[5], mine:{positions, totalText, percentileText}, rows (same as DayResult.rows), divisiveText, distribution, display}`. Hit ids: `review:back`, `review:retry`, `review:distribution`, `review:scroll`, `sheet:close`, `sheet:list`.
- Every archive vm carries `kind`: `'list'` (the list), `'review'` (day review), `'end'` (set end); the renderer dispatches on it. `nextAvailable` exists **only on the end vm**.
- Set end vm (after an archive play of 5 cards): `{kind:'end', totalText, bandLabel, rows, nextAvailable: bool, distribution, adState}`: "往期练习 {totalText} · 不计入排行"; hit ids `archive:again` (再来一期, only if `nextAvailable`), `archive:backList` (返回列表), `archive:distribution`. Logic runs the interstitial decision (`core/adpolicy.interstitialDecision`) on `archive:again` / `archive:backList`; render never knows about interstitials.

## overlay  (`overlay.js`, draw after any screen; copied from 点将台)
`vm = {dialog?, toast?, adStub?, privacy?, display?}`: `dialog {title?, text, confirmLabel, cancelLabel?, danger?}` -> `dialog:confirm`, `dialog:cancel`; `toast {text}` (no hits; logic removes it); `adStub {kind:'rewarded'|'interstitial', secondsLeft}` -> `adstub:complete`, `adstub:skip` (stub mode only, QA); `privacy {}` own-dialog fallback -> `privacy:agree`, `privacy:refuse`, `privacy:contract` (the spec §8.6 / E4 fallback; wired only if the device pass rules out the official popup).

## shareCard  (`shareCard.js`)
`render(canvas, model, {pixelScale?})` sets the canvas to 500 x 400 (5:4) and draws one of four models selected by `model.kind` (`render` receives `{kind: 'daily'|'round'|'reveal'|'group', ...model}`; logic adds `kind` to the models below), **always in the standard look** (ignores `display`). The models are built by `core/entry.js` and contain nothing else (AC 52, 53):
- `daily`: `dailyShareImageModel` = `{issueNo, rows:[{prompt, left, right, label}] x5, totalText, band, tagline}` — card labels as blocks, **no positions, medians or group numbers**.
- `round`: `roundImageModel` = `{left, right, clueLine, tagline}` — empty ruler, never the target.
- `reveal`: `revealImageModel` = `{left, right, target, guesses[], mqText}` (here `mqText` is a finished sentence, '本题默契值 78 · 5 人作答', drawn as is) — ruler with ▮ and unnamed ○, no names.
- `group`: `{title: '本群今日默契度 81' | '本群今日刻度'}` (only when `mq` exists for n >= 3).
A static fallback image path is used when rendering throws. Titles and queries: `core/entry.js` (`dailyShare`, `roundShare`, `revealShare`, `groupShare`, `menuShare`).

## open data domain  (`opendata/`)
Files: `index.js` (message loop, draw), `draw.js` (drawing), `board.js` (layout of rows; render), `match.js` + `peer.js` + `sha256.js` (**data model, logic-owned, tested in `tests/opendata.test.js`; do not change semantics**). The domain cannot require anything outside `opendata/`.
- Messages: `{type:'render', view:'group'|'friend'|'round', shareTicket?, groupid?, salt, selfHash, viewerDone, mode?:'full'|'selfOnly', dateKey, rows, refs?, anonymous?:true, target?, closestH?, width, height, dpr?, palette:'standard'|'highContrast', scale:1|1.25}` and `{type:'scroll', offset}`. `rows` is exactly the server rows: group `[h, gs, ns, t, pos|null, k|null]`; friend `[h, ns, t, pos|null, k|null]`; round `[h, g|null, s|null, late 0|1, isHost 0|1]`. Never post anything back. Field semantics: `anonymous: true` = names are unavailable (privacy or scope refused): draw the list as 群友 A/B/C without avatars or nicknames, do not read friend / group storage, no 好友自报 and no 最同频 line (你 and 出题人 keep their labels); `target` (round view) = the revealed target position, for 差 N 格; `closestH` (round view) = hash of the 最懂你 row; `mode` (friend view) = 'full' or 'selfOnly' as returned by the server; `refs` (friend view, only when the viewer completed) = the five national reference positions for the dot strip.
- Reads `getGroupCloudStorage({shareTicket | groupid, keyList:['kd']})` (group page; a round opened with a ticket) or `getFriendCloudStorage({keyList:['kd']})` (friend board; a round without a ticket), then `model = match.buildModel({view, serverRows: rows, salt, selfHash, kvList, viewerDone, mode, dateKey})`.
- Draw from `model.rows` **in the given (server) order**: `rank` + `name` ('你' for the viewer, '出题人' for the host row, nickname for a match, '群友 A/B/C' otherwise; `anonymous` rows get no avatar) + avatar + the values (group: 群内 `gs` and 全国 `ns`, streak `k` as "连N" when set; friend: score `ns`, optional 5-dot strip from `pos` relative to `refs` when the viewer completed; round: `g` as the guess, `s` as "+97", "差 N 格" from the target, `late` dashed and "揭晓后作答", `closestH` row tagged 最懂你 — `closestH` arrives in the main-domain reveal; pass it as `closestH` in the message for the round view). A 最同频 line "今天和你最同频：{peer.name}（平均只差 {peer.gapText} 格）" comes from `model.peer` (null = draw nothing). `model.selfReported` rows (friend `selfOnly`) draw as "好友自报" with no rank.
- Read failures (privacy / scope refused, API error) and empty lists are drawn **inside the canvas** as the anonymous list; the main domain separately shows `privacyDenied` / `unauthorized` chrome. KV values never rank, never override a server value (AC 43).

## Integration decisions (settled; enforced by the integration test the client-wiring wave adds)

- **One name per action.** The ids above are final; a renderer may not invent ids and logic may not route an id that is not listed. The integration test drives the real controller through every screen and state in the four display modes and cross-checks drawn ids, routed ids and this file.
- **Logic supplies everything the renderers read.** The test wraps each vm in a recording proxy: a property a renderer reads that the vm builder did not set fails (only the optional extras above may be absent), and drawn text containing `undefined`/`NaN`/`null` fails.
- **One text input in the game (AC 29, D-2):** the typed clue input on the create screen (`wx.showKeyboard` is called only from `js/keyboard.js` via the create flow, `maxLength: 12`). The only user-authored text ever drawn is a typed clue that passed the server's checks and is not hidden or paused (the round screen's clue line), plus WeChat nicknames inside the open data domain. Typed text never reaches events, share models or open data messages (AC 95, 96).
- **Ads in the render layer:** the only ad-related drawing is the ▶ 视频 buttons (result, create, archive end/review) and, in `ready`/`empty` board/list states, the banner placeholder; none is ever adjacent to 分享 or the ruler/primary (AC 55, 60).
- `packOptions.ignore` already excludes `tests`, `tools`, `node_modules`, this file and `core/README.md`.

- **Round rows (L4):** `[h, g, s, late, isHost]`; for a late row (`late` 1) `s` is `null` (a late guess never shows a score; the open data renderer already draws 揭晓后作答 there). On a revealed round the server may return `answerHidden: true` and no `reveal` until the viewer taps 直接看答案 (`getRound {showAnswer:true}`); the vm then keeps the existing 已揭晓 / 先猜再看 / 直接看答案 state (`revealedUnplayed`) and draws no markers.
