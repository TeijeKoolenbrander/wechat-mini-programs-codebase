# kedupan core (pure CommonJS, no wx)

Everything here is plain `module.exports` JS with **no wx, no DOM, no Node built-ins**: the client requires it, and
backend copies the whole `core/` folder into each cloud function (`scripts/sync-core.js`, drift test AC 7).
Mini games can only `require` `.js` files, so content is `.js` too. Spec: `docs/kedupan/spec.md` (section numbers below).

Positions are **integers 0..100**. A *hist* is a 101-element array of counts indexed by position.
References and distances may be half-integers. All scores are integers.

## date.js, rng.js (copied from dianjiangtai, unchanged)
- `beijingDateKey(ms)` -> `'YYYYMMDD'` (explicit UTC+8), `beijingMidnightMs`, `secondsSinceBeijingMidnight`, `dateKeyToMs`, `addDays(key, n)`, `daysBetween(a, b)`, `msUntilBeijingMidnight`, `issueNo(dateKey, launchKey)` (launch day = 1), `DAY_MS`.
- `sub(seed, name)` -> seeded `() => [0,1)` stream; `int(rng, n)`, `pick`, `shuffle(rng, arr)` (in place), `hash32`, `mulberry32`, `randomSeed()`.

## config.js
`getConfig(1)` -> `{ configVersion, daily{launchDateKey:'20261101', graceMs}, score{priorVotes:10, perStep:2.5, agreeRadius:10, agreeMinN:30, percentileMinN:30, groupMinForScore:2, groupMinForMq:3, groupRowCap:500, labels, bands}, rounds{...}, extras, ads, boardListCap, analytics }`.
`clampInterstitial(remote)` clamps `app_config.ads.interstitial` (everyNSets >= 2, minLifetimeSets >= 2, minGapSec >= 60, maxPerDay <= 8).
`normalizeFeatures(appConfig)` -> `{ subscribe:{tmplId}|null, banner:{enabled, adUnitId}, interstitial }` (what `getDaily.features` carries).

## score.js (spec 3)
| Function | Meaning |
|---|---|
| `cardScore(d)` | `max(0, 100 - ceil(2.5 d))` (3.1) |
| `scoreAt(p, ref)` | `cardScore(abs(p - ref))` |
| `labelFor(d)` | `{key, label}`: <= 2 心有灵犀, <= 6 很同频, <= 12 差不多, <= 20 有点偏, else 想法独特 |
| `medianOf(values)` / `medianFromHist(hist)` | 3.2 median `(v[floor((M-1)/2)] + v[floor(M/2)]) / 2`; `null` when empty |
| `nationalRef(hist, anchor, W=10)` | 3.3 `R_c`: median of real positions plus W votes at the item's anchor |
| `agreePct(hist, p)` | "和全国 x%": share within +-10 of p, **hist includes p**; `null` below 30 real positions |
| `madFromHist(hist, ref)`, `divisiveIdx(hists[5], refs[5])` | 今日最有争议 (highest national MAD, ties -> lower index) |
| `dayTotal(positions[5], refs[5])` | sum of card scores, skips `null` (unanswered) |
| `bandFor(total)` | `{key,label}`: >= 450 灵魂同频, >= 380 默契十足, >= 300 大体同频, >= 200 各有想法, else 独树一帜 |
| `histBins21(hist)` | 21 bins of 5 for 全国分布 (bin 20 = position 100) |
| `totalBin(total)`, `percentile(finalHist101, total, count, exactLower?)` | 定分 percentile = floor(100 * strictly-lower / count); `null` below 30 dailies. `finalHist` has 101 bins of width 5, so without `exactLower` totals in the viewer's own bin count as "not lower" |
| `looRef(positions, i)`, `groupScore(cards, i)` | 3.4 群内默契分 (leave-one-out; `cards[c][m]` = member m's position on card c; `null` for n < 2) |
| `groupCardMad(positions)`, `groupMq(cards)` | 群默契度 = round(mean over cards of `max(0, 100 - ceil(2.5 MAD))`); `null` for n < 3 |
| `groupMedian(positions)` | the daily reveal's ● (median of the OTHER members' positions; `null` if none) |
| `closestMate(viewerPos[5], others[{id, pos[5], t}])` | 最同频: smallest mean abs gap, ties -> smaller `t`; `{id, gap, gapText}` |
| `roundMq(guesses[{pos, late}], target)`, `bestGuess(guesses[{pos, ts, late}], target)` | 3.5 本题默契值 (rounded mean of on-time scores) and 最懂你 (ties -> earliest) |
| `newHist()`, `histCount(hist)`, `stepsBetween(from, to)` | helpers |

`ceilSafe` rounds to 1e-6 before `ceil`, so a MAD like 3.9999999999 does not score one point too low.

## content.js, content/ (spec 4)
- `getContent(1)` -> `{ contentVersion, categories, catLabel, spectra[], spectrumById, itemById, byCat, cardText(itemId) }`.
  `cardText(itemId)` -> `CardText { itemId, spectrumId, left, right, prompt, catLabel }` (never the anchor).
  `itemById[id]` -> `{ id, text, anchor, tags, spectrumId, cat, left, right }`.
- `pickSpectra(content, seed, count, excludeIds)`: host mode, seeded random spectra. `clueOptions(content, spectrumId, seed, batch)`: the 6 preset clue items for a batch (batch 1 = the next 6, wrapping).
- `content/spectra.v1.js`: the library (>= 300 spectra, >= 10 items each). Written compactly in `content/src/<category>.js` and expanded there; **ids are positional, append only**.
- `content/schedule.v1.js`: generated by `tools/build-schedule.js` (>= 365 days of 5 item ids; issue N = `days[N-1]`, issue 1 = `launchDateKey`).
- `content/forbidden.v1.js`: forbidden terms (CI); `content/calendar.v1.js`: season and festival dates.

## schedule.js (spec 4.2)
`buildSchedule(content, {launchDateKey, days, seed})`, `pickAutoDaily(content, dateKey, usedSet, recentSpectraSet)` (server auto path, deterministic by `sub(dateKey,'auto')`), `checkSchedule(content, schedule)` -> violations, `itemAllowedOn(item, dateKey)`.

## validate.js (spec 4.1, 4.3, 4.5, AC 8)
`validateStructure(raw)`, `validateForbidden(raw, extraStrings)`, `validateAll`, `termsIn(str)`, `visibleStrings(raw)`; each returns `[]` when clean.
