# Logic contract (minigame-dev <-> frontend-ui <-> backend), 传画接龙

Source of truth: `docs/chuanhua/spec.md`. Where this file and the spec differ, the difference is listed under "Reconciled decisions". The renderer side is `js/render/CONTRACT.md` (hit ids, per-screen vm extras, display modes, safety rules for drawing); this file is the logic side. Both are enforced by `tests/integration.test.js` (real controller + real renderers through every screen and display mode) and `tests/client-contract.test.js` (the same flows against the real cloud functions and the mock server).

## Who owns what

- `js/vm.js` (pure) builds the spec 12 view models. `js/controller.js` owns state, routing and the server calls, and assembles `view = { screen, vm, overlay, display, muted }` (`ctl.view(now)`). `js/renderers.js` loads `js/render/index.js`; there is **no stub renderer** (a renderer that throws is recorded in `renderers.errors`, the frame draws nothing, the loop survives; the integration test asserts the list stays empty).
- The renderers are pure: no wx, no timers, no state. Touch routing is `main.js`: a finger that starts on the topmost hit `draw:canvas` is a drawing gesture (`ctl.wantsPointer` / `ctl.onPointer`, never `onHit`); every other tap is `ctl.onHit(id)`; drags on a hit whose id is a key of `hits.scrollMax` call `ctl.onDrag(id, dy)`.

## What the controller adds to every screen vm (render/CONTRACT.md "Shared extras")

`display {largeText, highContrast}` (also on `overlay`), `t` (ms clock for skeletons and the caret), `scrollY` (offset of `scroll` or, on the reveal, `reveal:scroll`), `sheetScroll` (offset of `sheet:scroll`), `keyboardH` (px of the platform keyboard, from `wx.onKeyboardHeightChange`, 0 when closed), and the open sheet: `sheet` (`null|'rules'|'strike'|'howto'|'report'`) with `rules` (`{version, open, pendingAction, lines}`) or `report` (`{open, target:{chainId, step}, reasons, reasonLabels, reason (= selected), state, message}`). Scroll offsets reset when the screen changes. Overlay layers (`dialog`, `toast`, `adStub`) are in `view.overlay`; sheets are **not** (they travel in the vm).

Screen-specific extras the vm builders supply because renderers read them: `picker.drawSec`, `draw.coach/notice/sourceLabel/brushNames/brushSizes`, `describe.placeholder/focused`, `sent.title/canShare/explainerText`, `entry.headline/subline/primary/progressText`, `reveal.autoplay {enabled, panel, playing, progress}` (panel = index in the timeline, prompt 0; progress = 0..1 inside that panel), `reveal.replay {n, progress}` (one drawing replaying after a tap, only while it runs), `album.offlineNote/staleNote`, `settings.version/subscribeStatusText`, `detail.state` (`loading|ready|offline|error`).

## Hit ids

The ids and their documentation live in `js/render/CONTRACT.md` and nowhere else. The controller routes exactly those (plus `settings:feedback`, which is the native feedback button positioned by `main.js`). Rules the integration test enforces: every id a renderer draws is routed, every routed id is documented, every documented id is drawn by some real state (or is `entry:teaser`, drawn only for a state the controller never shows).

Behaviours worth knowing: `draw:timeUpOk` / `describe:timeUpOk` leave the 时间到 modal (the claim is already released when it opens); `draw:lock` / `describe:lock` swallow taps while a turn is locked; `settings:deleteAll` opens the first of two confirm dialogs (`overlay.dialog`; `vm.deleteAll.state` stays `idle` while they are open so the renderer does not draw a second dialog), `settings:deleteRetry` retries a failed delete; `picker:customOk` starts with the typed prompt, `picker:customCancel` closes the editor; `home:groupLine` and `home:group` both open 本群接龙; `entry:refresh` reloads the entry.

## Strokes and drawing

Format (core/README.md): `{v:1, s:[[c,w,x0,y0,dx,dy,...]]}`, 1024 grid, 12 colours, 3 sizes, <= 200 strokes / 4,000 points / 600 per stroke / 32 KB. `js/drawing.js` produces it from finger events with an allocation-free capture loop; `core/strokes.js` validates it on the client, `cloudfunctions/common/strokes.js` validates it again on the server (never trust the client). `js/render/strokes.js` draws it (round caps and joins, widths x k, quadratic smoothing through midpoints), `core/raster.js` (and the backend's `common/raster.js`) rasterise it for moderation. `tests/render-parity.test.js` pins: palette, brush widths, grid and limits identical in core / theme / backend; the renderer decodes the same absolute points as the core; client and server pictures differ in under 0.1% of pixels for dense (finger-sampled) input. The smoothing is a display nicety for dense input: a sparse polygon (a corner every 300 grid units) is cut visibly, which is why the tool samples every few pixels and the replay never resamples.

## Reconciled decisions (client, mock server, backend)

1. **Hit ids**: the renderer's ids are canonical (`picker:select:<id>`, `picker:shuffle`, `draw:submit`, `entry:group`, `entry:sameAgain`, `reveal:drawing:<n>`, `reveal:replayAll`, `reveal:sameAgain`, `teaser:sameAgain`, `teaser:group`, `group:start`, `settings:largeText`, `settings:highContrast`, `settings:terms`, `settings:deleteAll`, `rules:terms`, `strike:ok`, `howto:ok`); the controller was renamed to match.
2. **Sheets and display modes** travel in the vm (see above), not in `overlay.sheet`. The strike warning sheet is `sheet: 'strike'` (was `warn`).
3. **Ids**: `chainId` `[A-Z2-7]{10}`, `claimId` `[A-Z2-7]{12}`, `groupRef` `[0-9a-f]{16}`; malformed input is `BAD_INPUT` on both servers (the mock generates and validates the same formats; the client's card parser accepts only that format).
4. **joinGroup** input is the shape the backend sees after the platform decrypts `wx.cloud.CloudID`: `{groupData: {cloudID, data: {opengid, chat_type}}}` (the mock also accepts the old `mockData` alias).
5. **ackWarning** exists (cloud function): `getHome.me.warnPending` stays true until `ackWarning` (or `agreeRules`) clears it, so a crash before the sheet cannot lose the warning. Idempotent, never touches strikes.
6. **promptId** travels wherever 同题再传 needs it, preset prompts only and only where the viewer already sees the prompt: `getReveal` (participants), `getReveal` teaser, `getMyChains` items and `getMyChains({chainId})` items (revealed chain + participant, or expired chain + starter). `getChain` never returns a prompt (AC 10); its `canSameAgain` is true for revealed chains and, for expired ones, **only for the starter** (spec 8.7 says "everyone", but nobody else can learn the prompt without leaking it; AC 10 wins).
7. **getMyChains({chainId})** returns `{items:[{chainId,status,passed,length,mySteps,blockedStep,at,unseen,promptText,promptId,mine:[{n,kind,modState,strokes?,text?,canDelete}]}]}` for the caller's own 棒 only; `CHAIN_NOT_FOUND` if the caller is not involved. List items carry the same fields without `mine`, plus `streak` on the page; `cursor` is a number or null. `blockedStep` is null for a timed-out (void) 棒, the client then prints the neutral line.
8. **getChain** entry states are exactly core `entryState`: limits are `capReached` with `code` (`CAP_REACHED|STEP_LIMIT|CLAIM_LIMIT`), never `limit`; `restricted` carries `until`; `canRevealNow` is always a boolean; `activityId` only with `wantActivity`; extras `timeLeftMs takenEtaSec subscribed rulesRequired` exist on both servers.
9. **getReveal**: `state:'ready'|'paused'`, `promptId`, `canSameAgain`, `steps[].canReport`; non-participants get `NOT_PARTICIPANT` + teaser only if they are members of the chain's group, otherwise `NOT_MEMBER` (the client shows "找不到这条接龙", no hint that the chain exists). `CHAIN_HIDDEN` is treated like `CHAIN_REMOVED`.
10. **claimStep** with viewing switched off returns `{claimId:null, placeholder:'paused', prev:{kind:'paused'}}` and takes no lock (both servers); `timerSec` and `canReport` are on both.
11. **Reports**: step 0 (the teaser) hides the shown final sentence for a preset prompt and the whole chain for a custom prompt (both servers); `releaseClaim` is idempotent (`{released}`); `report` returns `{hidden, reopened, releasedOwnClaim}`.
12. **Error codes** are the backend's: unknown/malformed input is `BAD_INPUT` (was `BAD_PROMPT`, `BAD_REASON`, `BAD_KIND` in the mock), a step that is not yours is `FORBIDDEN` (was `OWN_STEP` for deletes), `NO_TEMPLATE` without a subscribe template, `REWARD_LIMIT` for a second no-fill grant of a kind per day.
13. **Share cards**: `inviteCardVm = {kind:'invite', passed, total:6}`, `revealCardVm = {kind:'reveal', promptText, finalText, passed, people}`; the static `assets/share-fallback.png` ships (without it WeChat screenshots the game canvas, which may contain a drawing).
14. **Time-up**: with nothing to send the claim is released and the 时间到 modal stays until `*:timeUpOk`; with a stroke / 2+ characters the turn is auto-submitted.
15. **Group list reasons** (`inProgress[].why`): `pending taken prevMine capReached` as in the spec, plus the backend's `restricted rules paused closed group` (the client prints a neutral line for each).
16. Sounds (`assets/sounds/*.mp3`) are optional: `audio.js` stays silent when a file is missing; no sound files are shipped yet.
