# 传画接龙 cloud functions (spec rev. 2: live rooms)

WeChat Cloud Development backend (cloud functions, cloud database, cloud storage) for the mini game. 33 functions, 18 `chuanhua_` collections, deny-all database and storage rules (one custom read rule for the content-free `chuanhua_room_signals`), moderation that fails closed. **Nothing in this folder deploys itself**: every step in "Founder deploy guide" is a manual console or DevTools action.

- Contract (binding): `CONTRACT.md`. Spec: `docs/chuanhua/spec.md` (rev. 2) sections 3A, 4, 5.8, 6, 7, 13, 16. Decisions: `docs/chuanhua/decisions.md` (TD-19 to TD-34 and TD-103 onward are this folder).
- Executable reference of the same behaviour: `../game/js/mock-server.js`. The contract test suite runs one set of scenarios against it **and** against these functions.

## Layout

```
cloudfunctions/
  <fn>/            33 folders (plain names): index.js, package.json, function.config.json (timeout), config.json (openapi permissions, timer)
  common/          source of truth for shared code; copied into every <fn>/common by `npm run sync`
  <fn>/core/       copy of ../game/core (rules shared with the client and the mock server); written by `npm run sync`.
                   The prompt bank (core/prompts.js, core/content/prompts.v*.js) is SERVER-ONLY: only the functions flagged `bank` in core/schema.js get it
  database/rules.json   generated by scripts/gen-rules.js: deny-all for every chuanhua_* collection except the owner-read rule of chuanhua_room_signals
  storage.rules.json    deny-all for cloud storage
  scripts/         sync-core.js (copy + drift check), scaffold.js (generates the deploy files from core/schema.js), gen-rules.js, deploy-pack.js
  tests/           contract suite, rooms, sync moderation, concurrency, admin, cleanup tests, fake database + fake SDK harness
```

Commands (from this folder): `npm test` (syncs, then runs every test), `npm run sync`, `npm run check` (drift of the copies, of the generated deploy files and of `database/rules.json`), `npm run scaffold` (regenerates package.json / function.config.json / config.json from `../game/core/schema.js`), `npm run rules` (regenerates `database/rules.json`), `npm run pack` (see step 3). Node 18 or later.

## Environment variables (console only, never committed)

Set per function in the console: 云开发 -> 云函数 -> the function -> 版本与配置 -> 环境变量 (the same names exist in `core/schema.js` `ENV_VARS`). `TZ=Asia/Shanghai` ships in each `function.config.json`. There is **no AppSecret and no payment key anywhere**: cloud calls need none (see the `750031` / HTTPS route in step 4 if the cloud call is not available).

| Variable | Functions | Values | Notes |
|---|---|---|---|
| `ENV_KIND` | every UGC function: the moderated chain functions (`createChain getChain claimStep releaseClaim submitStep onMediaCheck modSweeper getReveal revealNow laugh report getMyChains getGroupChains deleteMyStep`), `rollPrompts` and all room functions (`createRoom joinRoom leaveRoom startRoom getRoom submitRoomStep roomTick getRoomReveal rematch roomSweeper`) | `prod` or `dev`. **Unset or anything else = `prod`.** A typo in `ENV_KIND` is treated as `prod` (safer: live moderation, no mock verdicts). | Production: `prod`. |
| `MODERATION_MODE` | the same | `live` or `mock`. Unset = `live`. | Production: `live`. `mock` with `prod` (or an unknown mode) makes every UGC function answer `SERVER_CONFIG` and log `[ALERT]` (AC 51). |
| `MOD_TEXT_DAILY_BUDGET` | `createChain`, `submitStep`, `submitRoomStep` | integer, default 80 | Dev + live only: caps the text checks per day (the unpublished AppID allows about 100). |
| `MOD_IMAGE_DAILY_BUDGET` | `submitStep`, `submitRoomStep` | integer, default 200 | Dev + live only: caps `mediaCheckSync` per day (pre-publish quota is unknown, V16). Beyond it drawings fail closed (`MODERATION_BUSY`). |
| `MOCK_SYNC_DELAY_MS` | `submitStep`, `submitRoomStep` | integer, default 800 | Dev mock only: the simulated latency of the synchronous image check. |
| `MOCK_MEDIA_DELAY_SEC` | `submitStep`, `modSweeper` | integer, default 60 | Dev mock only, async fallback only. |
| `GROUP_REF_PEPPER` | `joinGroup` and every function that resolves a `groupRef` | a random string you generate, **at least 32 characters** (for example `openssl rand -hex 32`) | Salt of the opaque `groupRef`. Set once and keep it. Missing or shorter than 32 characters = every group-bound call refuses (`SERVER_CONFIG`, with an `[ALERT]` log line) (L5). |
| `ADMIN_OPENIDS` | `admin` | comma-separated openids, optional | Fallback if the console invocation turns out to carry an OPENID [V14]. Empty = nobody with an OPENID can use `admin`; the console (no OPENID) always can. |
| `PUSH_TOKEN` | `onMediaCheck` | the token you also type into the MP console | Only for the async-fallback HTTP route. Unset = that route is closed. |
| `PUSH_AES_KEY` | `onMediaCheck` | the 43-character EncodingAESKey | Only if the MP console is set to encrypted (安全) mode. |

**Production checklist:** `ENV_KIND=prod` and `MODERATION_MODE=live` on every UGC function (set them explicitly even though they are the defaults); `MOD_*` budgets, `MOCK_*` absent; no `MODERATION_MODE=mock` anywhere. Paste secrets into the console, never into chat or a commit.

## Security configuration (studio audit; keep these settings)

| Item | Required setting |
|---|---|
| **Anonymous / web login** | 云开发 -> 设置 -> 登录授权: **anonymous login and any web (Web SDK) login stay disabled.** The mini game is the only client; every call must carry a WeChat OPENID (`UNAUTHENTICATED` otherwise). Do not add a publishable key or a web domain. |
| **HTTP access service** | **Off for every function except `chuanhua_onMediaCheck`**, and that route only if the async-fallback HTTP route (step 4) is used. It is the one documented exception: the request is accepted only with a valid `PUSH_TOKEN` signature (`msg_signature` in the encrypted mode); without `PUSH_TOKEN` it is closed. Never expose `admin`, `modSweeper`, `roomSweeper` or `cleanup` over HTTP. |
| **Database** | `database/rules.json`: every collection `read: false, write: false`, except `chuanhua_room_signals` (custom read rule `doc._openid == auth.openid`, write `false`; step 1). Clients never write the database; they read nothing but their own doorbell. |
| **Cloud storage** | `storage.rules.json`: `read: false, write: false`. The PNGs are for the moderation service (a 10-minute temp link) and the admin review only. |
| **Timers** | `modSweeper`, `roomSweeper` and `cleanup` run only for the platform's timer event `{"Type":"Timer"}`; a call that carries an OPENID is `FORBIDDEN`, and so is one without the marker. For a manual run from the console use the test event `{"Type":"Timer"}`. |
| **`GROUP_REF_PEPPER`** | At least 32 characters (see the table above). |
| **joinGroup** | The client sends the raw `cloudID` string of `wx.getGroupEnterInfo`; the function decrypts it itself with `cloud.getOpenData({list:[cloudID]})` ([official reference](https://developers.weixin.qq.com/minigame/dev/wxcloud/reference-sdk-api/open/Cloud.getOpenData.html)). It requires a falsy `errCode`, an `opengid`, and a `chat_type` that is absent or 3 / 4 (studio ruling); a payload with only `open_single_roomid` (a single chat) is refused (`NOT_GROUP`). It never reads `event.groupData`. Do not wrap the cloudID in `wx.cloud.CloudID()` on the client. |
| **Rate limits** (per openid, fixed one-minute window, `RATE_LIMITED`) | reads 60/min: `getHome getChain getReveal getMyChains getGroupChains getRoom getRoomReveal`; turns 30-40/min: `submitRoomStep` 30, `submitStep` 30, `roomTick` 40; writes 20/min: `claimStep releaseClaim joinGroup laugh agreeRules subscribeReveal track rollPrompts`; tighter: `createChain` 5, `createRoom` 5, `startRoom` 5, `rematch` 5, `joinRoom` 10, `leaveRoom` 10, `deleteMyStep` 10, `report` 10, `revealNow` 10, `grantReward` 10; `admin` (allow-listed openid only) 60. |
| **`track`** | Allowlists props per event from the spec 14 catalogue (`game/core/analytics.js` `EVENT_PROPS`): unknown keys, wrong types and out-of-enum values are dropped. |
| **Prompt bank** | Server-only (TD-103): `rollPrompts` and the room functions return only the 3 rolled texts. The bank is not in the client package. |

## Founder deploy guide

Prerequisites: the AppID, a cloud environment, WeChat DevTools (cloud development enabled), console access. Do these in order. Handoff items H4 and H5 in the spec are this list.

### 1. Database

1. Create these 18 collections (names include the prefix): `chuanhua_chains chuanhua_steps chuanhua_rooms chuanhua_room_signals chuanhua_mod_traces chuanhua_mod_log chuanhua_mod_quota chuanhua_reports chuanhua_players chuanhua_group_members chuanhua_group_stats chuanhua_reactions chuanhua_sub_grants chuanhua_daily_stats chuanhua_audit_log chuanhua_events chuanhua_rate_limits chuanhua_app_config`. (`chuanhua_meta` of rev. 1 is gone: there is no daily prompt.)
2. For **each collection except `chuanhua_room_signals`**: 权限设置 -> 自定义安全规则 -> paste `{ "read": false, "write": false }` (the value in `database/rules.json`). Why every one is deny-all (AC 57): the game never reads or writes these directly; every read and write goes through a cloud function, which runs with admin rights and bypasses the rules. Any weaker rule would let a modified client read other players' drawings, write allowances or fake a verdict. Strictest setting that works.
3. **The custom `watch` rule (the one exception).** `chuanhua_room_signals` -> 权限设置 -> 自定义安全规则 -> paste
   ```json
   { "read": "doc._openid == auth.openid", "write": false }
   ```
   Why: real-time sync is a doorbell. The client `watch()`es its own signal document (`where({_openid: '{openid}', roomId})`); the platform applies the collection's read rule to `watch` as well ("集合的读权限设置在实时数据推送里同样生效"), so a player can see only their own documents. A signal holds only the room id, `seq`, state, round, kind, phase, deadline, `serverNow`, two counts and the owner's `_openid`: **no content and no other player's openid**. Only the functions write it (they set `_openid` explicitly) [VERIFY V18]. If the platform refuses this rule or `watch` fails on the device pass, set `app_config.rt.watch` to `false`: the client then polls `getRoom` every 2 s and nothing else changes (V17).
4. Create the indexes (索引管理), fields in this order:

| Collection | Indexes |
|---|---|
| `chuanhua_chains` | `openGId + state + lastActivityAt`; `state + expiresAt`; `participants`; `createdAt`; `state + createdAt`; `roomId` |
| `chuanhua_steps` | `author + createdAt`; `chainId`; `chainId + claimId`; `state + mod.submittedAt` |
| `chuanhua_rooms` | `openGId + state + lastActivityAt`; `state + deadline`; `state + lastActivityAt`; `seats.openid + state`; `createdAt` |
| `chuanhua_room_signals` | `_openid + roomId`; `roomId` |
| `chuanhua_mod_log` | `stepId`; `ts` |
| `chuanhua_reports` | `state + createdAt`; `stepId`; `createdAt` |
| `chuanhua_players` | `lastActiveAt`; `flagged` |
| `chuanhua_group_members` | `openGId + lastSeen`; `openid` |
| `chuanhua_group_stats` | `lastActivityAt` |
| `chuanhua_reactions` | `createdAt` |
| `chuanhua_sub_grants` | `used + chainId`; `grantedAt` |
| `chuanhua_audit_log` | `ts` |
| `chuanhua_events` | `ts`; `name + ts` |
| `chuanhua_rate_limits` | `expireAt` |
| `chuanhua_mod_traces`, `chuanhua_mod_quota`, `chuanhua_daily_stats`, `chuanhua_app_config` | none (`_id` only) |

Each index serves a query in the code: `getHome` / `getGroupChains` / `roomSweeper` (`openGId + state + lastActivityAt`, `state + deadline`, `state + lastActivityAt`), `getMyChains` and `getHome` (`seats.openid + state`, `author + createdAt`, `participants`), the room listener (`_openid + roomId`), signal cleanup (`roomId`), the sweeper's expiry scan (`state + expiresAt`) and pending-drawing scan (`state + mod.submittedAt`), idempotent submit (`chainId + claimId`), cleanup (`createdAt`, `state + createdAt`, `lastActiveAt`, `lastSeen`, `ts`, `expireAt`, ...), `admin listReports` (`state + createdAt`), reveal notices (`used + chainId`).

5. Create the config document (console -> `chuanhua_app_config` -> 添加记录; the code works without it, with these defaults), `_id` = `live`:
   ```json
   { "ugc": { "createEnabled": true, "viewEnabled": true },
     "features": { "updatableCard": false, "liveRooms": true },
     "moderation": { "imageMode": "sync", "textApi": "game" },
     "room": { "minPlayers": 3, "maxPlayers": 10, "maxRounds": 4, "promptSec": 30, "drawSec": 60, "describeSec": 45, "graceSec": 5, "lobbyIdleMin": 30, "gameMaxMin": 20 },
     "rt": { "watch": true, "pollSec": 2, "safetyPollSec": 10 },
     "subscribe": { "tmplId": "", "fields": { "title": "thing1", "prompt": "thing2", "time": "time3" } },
     "timers": { "drawSec": 60, "describeSec": 45 } }
   ```
   Leave `subscribe.tmplId` out until the one-time template exists (H7); `features.updatableCard` stays `false` until the device pass proves updatable messages (V7, V21). Kill switches take effect within 10 s. `moderation.imageMode: "async"` switches **live rooms off** (see step 4).

### 2. Cloud storage

云开发 -> 存储 -> 权限设置 -> custom rule from `storage.rules.json` (`{ "read": false, "write": false }`): clients never read or write a file. Only `submitStep` and `submitRoomStep` write `chuanhua/mod/<YYYYMM>/<chainId>/<n>_<attempt>.png`; only the content-security service (through a 10-minute temp link for the synchronous check) and `admin` (10-minute links) read it. PNGs never reach a client (PO-10, AC 29). If custom storage rules are not available in the mini game environment [V9], keep the default rule 仅创建者及管理员可读写: the creator is the server, so it denies everyone else as well.

### 4. Content security (H5) and the synchronous image check (V16)

Live rooms need the **synchronous mini-game image check**. This is the first thing to prove (device pass step 1).

1. **Cloud call permissions.** Cloud calls need no AppSecret. The permissions `wxa.game.contentSpam.mediaCheckSync` and `wxa.game.contentSpam.msgSecCheck` (and the fallbacks `security.msgSecCheck`, `security.mediaCheckAsync`) are declared in each `config.json` and applied by the upload; check in 云开发 -> 云函数 -> the function -> 云调用权限 that they are listed. API: [`gamesecurity.mediaCheck`](https://developers.weixin.qq.com/minigame/dev/api-backend/wxa-sec-check/api_gamesecurity.mediacheck.html), cloud call `cloud.openapi.wxa.game.contentSpam.mediaCheckSync` (mini game accounts only; 2,000 calls/min, 200,000/day per AppID; the functions use a 5 s timeout and `media_type 2`, `version 2`, `scene 3`).
2. **Enablement and the `750031` path.** Error **`750031`** means "game not supported, contact the mini-game team to configure". If it appears (function log of `chuanhua_submitRoomStep` or `chuanhua_submitStep`, or an `[ALERT]` line), the code does three things by itself: the drawing is **not** delivered (fail closed, `MODERATION_BUSY`), `app_config.moderation.imageMode` is set to **`async`** and an `[ALERT]` is logged. In `async` mode `getHome` reports `features.liveRooms: false`, `createRoom` answers `LIVE_OFF`, `roomSweeper` finishes rooms in play (their remaining slots become markers), and 慢慢传 uses the old asynchronous pipeline (message push below). **Founder action:** ask WeChat (小游戏 team / 管理后台 客服) to enable the game content-security interface for this AppID, then run `chuanhua_admin` with `{ "op": "setModeration", "imageMode": "sync" }` and re-test. If the cloud call is unavailable altogether (the SDK has no `openapi.wxa.game.contentSpam`), the HTTPS route needs the AppSecret in the cloud environment config (never pasted in chat or committed) and a code change; until then stay in `async` and escalate. Quota errors `750032`/`750033` are plain `MODERATION_BUSY` and do not switch the mode. At 70% of 200,000/day the log shows `[ALERT]`: ask WeChat for a raise (H11); at 95% `createRoom` and `createChain` answer `UGC_BUSY`.
3. Run `chuanhua_modSweeper` and `chuanhua_roomSweeper` once from the console with the test event `{"Type":"Timer"}`: each must answer `{ "ok": true, ... }`. A `SERVER_CONFIG` answer means `ENV_KIND`/`MODERATION_MODE` are wrong (the log carries an `[ALERT]` line).
4. **Message push for `wxa_media_check` (async fallback only, V1).** Needed only if `imageMode` is ever `async`. Primary route: 云开发控制台 -> 设置 -> 其他设置 -> 消息推送 -> 推送模式 **云函数** -> 添加配置:

   | Field | Value |
   |---|---|
   | 消息类型 (MsgType) | `event` |
   | 事件类型 (Event) | `wxa_media_check` |
   | 环境 | the cloud environment |
   | 云函数 | **`chuanhua_onMediaCheck`** |

   The function returns `success` and ignores every other event type. If the console does not offer `wxa_media_check`, use the HTTP route:
   - 云开发 -> HTTP 访问服务 -> add a path bound to `chuanhua_onMediaCheck` only (**the one HTTP-route exception**: no other function has an HTTP path).
   - MP 后台 -> 开发管理 -> 开发设置 -> 消息推送: URL = that path's full URL, Token = a random string (also set it as `PUSH_TOKEN` on `chuanhua_onMediaCheck`), 数据格式 **JSON**, mode 明文 or 安全 (for 安全 also set `PUSH_AES_KEY` = the EncodingAESKey). The function answers the URL check (`echostr`) and accepts a POST only with a valid signature; without `PUSH_TOKEN` the route is closed.
5. Verify (device pass step 1): in a **dev** environment with `ENV_KIND=dev`, `MODERATION_MODE=live` send 20 drawings and 20 texts; record `mod_verdict` `latencyMs` p50/p95, error codes and the quota behaviour (`chuanhua_events`, name `mod_verdict`, props `api` `game`).
6. Watch the logs for lines starting with `[ALERT]`: `mediaCheckSync` 750031, image quota at 70%, circuit breaker tripped, open report older than 48 h, mock moderation in production, moderation PNG upload failed, HTTP push rejected.

### 5. Daily operation (H9)

Run from the console (云函数 -> `chuanhua_admin` -> 云端测试, an empty OPENID): `{ "op": "listReports", "state": "open", "limit": 50 }` and `{ "op": "sample", "n": 20 }` (optional `kind`, `mode`: `live` or `chain`) daily for the first 4 weeks, then every 2 days. Other ops: `getStep {stepId}` (shows the author's openid, active strikes and a 10-minute PNG link), `upholdReport {reportId}` (one strike), `dismissReport {reportId, restore}`, `hideStep` / `restoreStep {stepId}`, `removeChain {chainId}`, `removeRoom {roomId}` (every chain of the room removed, a room in play ended), `restrict {openid, days | permanent}`, `liftRestriction {openid}`, `setUgc {createEnabled?, viewEnabled?}` (the kill switches; `createEnabled: true` also ends an automatic pause; `createEnabled: false` finishes rooms in play within a minute), `setModeration {imageMode?: "sync"|"async", textApi?: "game"|"general"}` (`async` finishes rooms in play and closes lobbies at once). Every op writes `chuanhua_audit_log`. Reported items are hidden at once, so a slow queue never exposes content.

## How moderation fails closed (spec 6, compliance)

- **Text** (custom prompt, description): local rules -> the game `msgSecCheck` (`version 2`, `scene 3`, the author's context openid, 2 s timeout; `textApi: general` uses the general v2 API with a 3 s timeout, where `review` blocks without a strike) -> `pass` stored and visible; `risky` blocked + one strike. API error, timeout, quota error, a non-zero `errCode`, an empty or unknown verdict = `MODERATION_BUSY`, nothing stored, nothing shown.
- **Drawings (default `imageMode: sync`)**: strokes validated (core limits, `h` 768-2048, the ink budget) -> PNG of 512 x round(512 h / 1024) rasterised on the server -> cloud storage -> 600 s temp link -> `mediaCheckSync` (5 s timeout) -> `pass` delivered; `risky` blocked + one strike; error, timeout, 750032/750033, upload failure, unknown verdict = `MODERATION_BUSY`; **750031** additionally switches the mode (step 4). A forced send that does not pass becomes the marker 「（这一棒没传过来）」 in a live room and reopens the 棒 in 慢慢传; nobody ever sees unchecked content.
- **Drawings (`imageMode: async`, fallback)**: the v1 pipeline: `mediaCheckAsync` -> `pending` -> push to `onMediaCheck`; failed calls retried at +5 / +10 min, 35 minutes without a verdict = one re-check, then `void` (no strike, allowance restored).
- **Configuration**: `ENV_KIND`/`MODERATION_MODE` are checked first by every UGC function; mock in production, an unknown `MODERATION_MODE` = `SERVER_CONFIG` + `[ALERT]`.
- **Guards**: kill switches (`createEnabled`, `viewEnabled`, 10 s), circuit breaker (50% of >= 20 calls in 5 min pauses creation 15 min), image quota (alert 70%, `UGC_BUSY` 95%, drawings refused 100%), the dev live budgets.
